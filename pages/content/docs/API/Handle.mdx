<Callout title="Client Only" type="info">
    This class is only available when running on the client.
</Callout>

A Handle is the core primitive of Fragment. It binds a renderer function to a specific UI Instance resolved via a path from `PlayerGui`, and re-runs that renderer whenever its subscribed data or state changes.

Handles manage:

- Rendering and effect lifecycles
- Local reactive state slots
- Derived and memoized values
- Async state helpers
- Named signal connections
- Store and Context subscriptions
- Diffing containers for dynamic children

---

# Render-cycle methods

These methods are only active **inside a renderer or an Effect callback**. Calling them outside produces a warning and does nothing.

## `Effect(fn, deps?)`

Registers a side-effect that runs after the render. If `fn` returns a cleanup function, it runs before the effect's next run.

<TypeTable
  type={{
    Effect: {
      description: "Registers a side-effect. The returned cleanup function runs before the effect's next run.",
      type: "(fn: () -> (() -> ())?, deps: { any }?) -> ()"
    }
  }}
/>

<Callout title="deps works like derive's" type="info">
    With no `deps`, the effect tears down and reruns on **every** render — the original behavior. Pass a `deps` array (same shallow-equal comparison as [`derive`](#handlederivefn-deps)) to skip teardown/rerun entirely when nothing in it changed, e.g. a connection that only needs re-wiring when the target Instance changes, not on every unrelated state update.
</Callout>

**Example**:
```luau title="ClockHandle.luau"
Handle.Effect(function()
    local conn = RunService.Heartbeat:Connect(function()
        element.Text = os.date("%H:%M:%S")
    end)

    return function()
        conn:Disconnect() -- [!code highlight]
    end
end) -- no deps: reconnects every render

Handle.Effect(function() -- [!code highlight]
    print("target changed:", targetId()) -- [!code highlight]
end, { targetId() }) -- [!code highlight] -- skips teardown/rerun while targetId() is unchanged
```

## `Connect(connName, signal, callback)`

Binds a named connection slot to an `RBXScriptSignal`.

<TypeTable
  type={{

      type: "(connName: string, signal: RBXScriptSignal, callback: (...any) -> ()) -> ()"

**Example**:

## `RegisterContainer(frame)`

Returns a persistent [Container](/API/Container) for `frame` that diffs children across renders.

<TypeTable
  type={{
    RegisterContainer: {
      description: "Returns a persistent diffing Container for the given frame.",
      type: "(frame: Instance) -> Container"
    }
  }}
/>

<Callout title="Available inside Effects" type="info">
    `RegisterContainer` can be called both at the top level of a renderer and inside `Effect` callbacks.
</Callout>

**Example**:
```luau title="LeaderboardHandle.luau"
local list = Handle.RegisterContainer(element.ScrollFrame) -- [!code highlight]

for i, entry in ipairs(data.entries) do
    local row = Fragment.useComponent("LeaderboardRow", { name = entry.name, score = entry.score })
    list.UpsertChild(entry.id, row)
end
```

# Bindings

Bindings are slots that persist across renders. They must be called **in the same order on every render**.

## `handle:bind(initialValue)`

Creates a reactive state slot inside the renderer. The slot is initialised once on the first render.

<TypeTable
  type={{
    bind: {
      description: "Creates a reactive state slot. Returns a getter and a setter. The setter triggers a deferred re-render if the value changed.",
      type: "(initialValue: any) -> (() -> any, (any) -> ())"
    }
  }}
/>

Returns:
- **getter**: `() -> any` — reads the current value
- **setter**: `(any) -> ()` — updates the value and queues a re-render

**Example**:
```luau title="TabsHandle.luau"
local tabIndex, setTabIndex = Handle:bind(1) -- [!code highlight]

for i, tab in ipairs(tabs) do
    local live = container.UpsertChild(tab.name, Assets.Tab:Clone())
    live.Active = tabIndex() == i

    Handle.Connect("Tab_" .. tab.name, live.Activated, function()
        setTabIndex(i)
    end)
end
```

<Callout title="Batched" type="info">
    Calling several setters in the same tick — two `bind` setters, a store update and a context patch, anything — produces exactly one render, not one per call. Fragment coalesces them the same way React 18's automatic batching does.
</Callout>

## `handle:spring(initialValue, config?)`

Creates a value that animates toward whatever target the setter is given, using damped spring physics instead of jumping straight there — the same idea as Fusion's `Spring`. The getter keeps changing on its own (via a shared `RunService.Heartbeat`) until it settles on the target.

<TypeTable
  type={{
    spring: {
      description: "Creates an animated value. Returns a getter and a setter for a new target.",
      type: "(initialValue: any, config: { frequency: number?, damping: number? }?) -> (() -> any, (any) -> ())"
    }
  }}
/>

- `frequency` — oscillations per second if undamped (default `4`)
- `damping` — `1` = critically damped, `< 1` = bouncy, `> 1` = sluggish (default `1`)

<Callout title="Supported types" type="warn">
    `number`, `Vector2`, `Vector3` and `UDim2` animate correctly (`UDim2` is decomposed into its four scalar components, since it has no scalar multiplication). Any other type — `Color3`, which Roblox gives no arithmetic operators at all — can't be integrated this way and just snaps straight to the target.
</Callout>

**Example**:
```luau title="HoverCard.luau"
local size, setSize = Handle:spring(UDim2.fromOffset(100, 40), { frequency = 4, damping = 1 }) -- [!code highlight]

Handle.Connect("Hover", element.MouseEnter, function()
    setSize(UDim2.fromOffset(120, 48)) -- [!code highlight]
end)
Handle.Connect("Unhover", element.MouseLeave, function()
    setSize(UDim2.fromOffset(100, 40)) -- [!code highlight]
end)

element.Size = size()
```

## `handle:derive(fn, deps)`

Returns a getter whose value is recomputed only when `deps` changes.

<TypeTable
  type={{
    derive: {
      description: "Returns a getter that recomputes its value only when deps changes.",
      type: "(fn: () -> any, deps: { any }) -> () -> any"
    }
  }}
/>

**Example**:
```luau title="IndexWindow.luau"
local getFiltered = Handle:derive(function() -- [!code highlight]
    return superDuperTableFilterFunction(allItems, function(item) -- [!code highlight]
        return item.tier == currentTier -- [!code highlight]
    end) -- [!code highlight]
end, { currentTier }) -- [!code highlight]

for _, item in ipairs(getFiltered()) do
    -- render item
end
```

## `handle:hold(fn, deps)`

Returns a stable function reference. The same function object is returned as long as `deps` is unchanged.

<TypeTable
  type={{
    hold: {
      description: "Returns a stable function reference. Only replaced when deps changes.",
      type: "(fn: (...any) -> any, deps: { any }) -> (...any) -> any"
    }
  }}
/>

**Example**:
```luau title="ShopHandle.luau"
local onBuy = Handle:hold(function() -- [!code highlight]
    purchaseItem(selectedItem()) -- [!code highlight]
end, { selectedItem() }) -- [!code highlight]

Handle.Connect("BuyBtn", buyButton.Activated, onBuy)
```

## `handle:await(fn, deps?)`

Runs `fn` asynchronously and returns a status table. Triggers a re-render when the operation settles.

<Callout title="Non-blocking" type="info">
    `await` uses `task.spawn` internally and never yields the renderer. The renderer immediately receives a `"pending"` status table and re-renders again once the operation resolves.
</Callout>

<TypeTable
  type={{
    await: {
      description: "Runs fn asynchronously and returns a reactive status table.",
      type: "(fn: () -> any, deps: { any }?) -> { status: string, value: any, error: any }"
    }
  }}
/>

`status` is one of:
- `"pending"` — operation in progress
- `"resolved"` — completed successfully, `value` holds the result
- `"rejected"` — failed, `error` holds the message

**Example**:
```luau title="ShopHandle.luau"
local inventory = Handle:await(function() -- [!code highlight]
    return InventoryService:FetchAsync() -- [!code highlight]
end, { store.lastUpdated }) -- [!code highlight]

if inventory.status == "pending" then
    element.Spinner.Visible = true
    return
end

element.Spinner.Visible = false

if inventory.status == "resolved" then
    for _, item in ipairs(inventory.value) do
        -- render item
    end
end
```

## `handle:attribute(instance, attributeName)`

Subscribes to a replicated Instance [Attribute](https://create.roblox.com/docs/studio/properties#instance-attributes) and returns a getter for its current value. Whatever sets it — a server script via `instance:SetAttribute`, ReplicaService, Knit, a plain RemoteEvent handler — shows up here reactively, through Roblox's own attribute replication, without Fragment depending on any particular networking library.

<TypeTable
  type={{
    attribute: {
      description: "Subscribes to a replicated Attribute. Returns a getter for its current value.",
      type: "(instance: Instance, attributeName: string) -> () -> any"
    }
  }}
/>

<Callout title="Fixed on first call, like bind" type="info">
    The `(instance, attributeName)` pair is fixed the first time this slot is called — calling it again with a different instance/name on a later render does not re-subscribe.
</Callout>

**Example**:
```luau title="CoinsHandle.luau"
local getCoins = Handle:attribute(player, "Coins") -- [!code highlight]

element.Text = `Coins: {getCoins()}`
```

## `Unmount()`

Tears a handle down for good: runs every effect cleanup, disconnects every `Connect`/visibility/attribute connection, removes it from every store and context it subscribed to via `useStore`/`pull`, and cancels any spring still animating on it. Idempotent — safe to call more than once.

<TypeTable
  type={{
    Unmount: {
      description: "Tears down a handle: effects, connections, store/context subscriptions, springs.",
      type: "() -> ()"
    }
  }}
/>

<Callout title="Mostly for Fragment.mount" type="info">
    `newHandle`-created handles are meant to live for the whole session and never need this. It exists for handles that come and go on their own — [`Fragment.mount`](/API/Fragment#mountcontainer-renderer) is the main one.
</Callout>

**Example**:
```luau
local handle = Fragment.mount(container, renderer)

-- later, when the preview/tooltip/whatever goes away
handle:Unmount() -- [!code highlight]
```
